# Design System: Jefferson Veloso Portfolio

## Overview

**Creative North Star: "The Product Page for an Engineer"**

The home page presents Jefferson the way Apple presents a product. The UI chrome follows the owner-pinned Apple product-page language in `DESIGN-APPLE.md`: full-bleed tiles alternating white, parchment and near-black; one quiet blue for every action; SF Pro (Inter off Apple platforms) set tight; pill CTAs; a single soft product shadow. That file is the binding reference grammar and is not edited. This file records how the build applies it and where the build adds a world of its own.

Apple's "product photography" is drawn in CSS here. A silver 65% mechanical keyboard is the hero render: white alphas, graphite modifiers, a blue return key that is a real "Email me" link, and the classic six-colour rainbow stripe as the typing glow. The same keycap material comes back as project keysets, a six-key workflow macro, the contact return key and the skill chips. A macOS code window with Xcode-dark syntax colours shows him as code. All colour beyond the action blue lives inside these objects. The chrome around them stays white, grey and black.

Density is low and the pace is a product launch. Each tile carries one idea, centred: title, one-line lead, proof, with the render as the centrepiece. Motion is mechanical: keys travel down, light in a stripe colour and cool back. Every animated object also has a still, complete state for reduced motion. The direction contract explicitly rejects the dark "Hi, I'm" developer hero with a tech-icon grid.

**Key Characteristics:**
- Apple chrome (owner-pinned): white, parchment and near-black tiles edge to edge, with the colour change as the divider.
- One action colour: Action Blue pills and links, and Sky on dark tiles.
- Colour is material: keycaps, the rainbow-stripe backlight, Xcode syntax and macOS traffic lights.
- One product shadow, only under keyboard cases and the code window.
- One keycap material at every scale: hero board, keysets, macro, return key and skill chips, all drawn from a single CSS keycap sized by its key unit.
- Physical motion: 140ms key travel, a 50ms glow-on and a 900ms cool-down. With reduced motion, renders show their finished state.

## Colors

A greyscale Apple chassis with one blue for action. A full colour range exists only inside the rendered objects.

### Primary
- **Action Blue** (#0066cc): every UI action. It fills the "Email me" pills, draws ghost-pill borders and text and text links on light tiles, and colours the hero board's return key and the contact return key, which are both real mailto links. It is also the caret colour. Filled pills darken to **Action Hover** (#0058b0) on hover, which keeps white text at 6.95:1 (Apple's own brighter #0077ed fails AA at 4.32:1).
- **Focus Blue** (#0071e3): the 2px solid focus outline (2px offset) on every focusable element. On keycaps it draws around the cap, not the hit box.
- **Sky** (#2997ff): Action Blue's dark-tile form, used for text links and ghost pills (Copy email) on near-black tiles. Inside the code window, at 18% alpha, it is the debugger's current-line highlight.

### Secondary
The keycap colourways. Each tone is a triple: a sculpted **top** face, the visible **side** (skirt) and a darker **base** edge under it.
- **Silver Alpha** (top #fbfbfd, side #e7e8ec, base #c6c8cf, legend Graphite): letters, digits and punctuation, keyset alternates, and the space bar. It also forms most skill chips.
- **Graphite Modifier** (top #4a4a4d, side #3a3a3c, base #1f1f21, legend Parchment): modifiers and arrows, the five top-stack skill chips, and the nav logo mark.
- **Action Keycap** (top #1170d0, side Action Blue, base #004c99, legend white): only on keys that are links (hero Enter, contact return) and on the favicon.
- **Valueva Green** (top #6cc451, side #57ad3d, base #3e8a29, legend Graphite): the esc key, the macro's final "ship" key and the Valueva keyset.
- **Conciliador Purple** (top #a24ea3, side #8a3a8b, base #682a69, legend white): the Conciliador keyset.
- **Class Yellow** (top #fdc23a, side #f0ad18, base #c98c06, legend Graphite): the English in Class keyset.
- **Bistrô Orange** (top #f9963f, side #ec7d1c, base #b85f0b, legend Graphite at 6.0–7.6:1): the case study's split keyset.
- **Brushed Case** (#eeeff2 to #d4d6db, top to bottom): the aluminium case gradient under every board and keyset.

### Tertiary
- **Rainbow Stripe** (Green #61bb46, Yellow #fdb827, Orange #f5821f, Red #e03a3e, Purple #963d97, Blue #009ddc, always in that order): the typing glow and backlight. Legends turn Graphite on the first three and white on the last three. The name keys on the hero board, the macro keys and the share image's keycap strip all cycle through it in order.
- **Xcode Dark** (Plain #e5e5e7, Punctuation #a8a8ad, Keyword #fc5fa3, String #fc6a5d, Comment #8d99a5, Type #5dd8ff, Function #67b7a4, Property #a5d6ff): syntax tokens in the code window. The console reuses Comment for its prompt, Plain for step names and Punctuation for results.
- **macOS Window** (body #1e1e20, title bar #2c2c2e, console #19191b, title #a1a1a6, toolbar control #c7c7cc, gutter #8e8e93; traffic lights #ff5f57, #febc2e, #28c840): the window chrome. The console's check marks reuse the green traffic light.

### Neutral
- **Canvas** (#ffffff): the hero, light tiles and utility cards. It is also the text colour on dark tiles and on filled pills.
- **Parchment** (#f5f5f7): alternating light tiles, the frosted sub-nav (at 80%), the footer and mod-key legends.
- **Tile 1 / Tile 2 / Tile 3** (#272729 / #2a2a2c / #252527): near-black tiles. Tile 1 is used for Meet and Contact, Tile 2 for the featured project and Tile 3 for the case study.
- **Nav Black** (#000000): the global nav, plus the browser theme colour. It appears nowhere else.
- **Graphite** (#1d1d1f): all headline and body text on light surfaces, alpha legends and the skip link.
- **Graphite 80** (#333333): supporting paragraphs on light tiles, the sub-nav status line and footer links.
- **Secondary** (#6e6e73): fact labels, dates, tool lists, captions and fine print on light surfaces.
- **Mist** (#cccccc): secondary copy and fact labels on near-black tiles.
- **Hairline** (#e0e0e0): the 1px border of utility cards and the footer's column rule.
- **Divider** (#f0f0f0): row rules inside utility cards.
- **Selection** (#b3d7ff): the macOS text-selection highlight, with Graphite text.
- Translucent rules: white at 15% on dark tiles, black at 10% on light tiles and black at 8% under the sub-nav. Integration roles use Secondary, and experience bullets are 6px Graphite dots at 40%.

### Named Rules
**The One Blue Rule.** In the UI, Action Blue (Sky on dark tiles) means "act here" and marks nothing else. Pills, text links and the two link keycaps are the only places it appears. A keycap is blue only if it is a link.

**The Colour Is Material Rule.** Every other hue belongs to an object: a keycap, a backlight, a syntax token, a traffic light. No stripe, keycap or syntax colour ever becomes a background, heading, border, link or body-text colour.

**The AA Grey Rule.** Grey copy on light surfaces is Secondary (#6e6e73). Apple's #7a7a7a fails AA at caption size, so the build replaced it. It stays defined in `@theme` but is never used for text.

## Typography

**Display Font:** SF Pro via `-apple-system, BlinkMacSystemFont, "SF Pro Text"` on Apple platforms (with Inter, loaded through `next/font`, then Helvetica Neue and Arial elsewhere)
**Body Font:** the same stack
**Label/Mono Font:** `ui-monospace, "SF Mono", SFMono-Regular, Menlo` (with Geist Mono off Apple platforms)

**Character:** One family at two UI weights, set tight, as `DESIGN-APPLE.md` pins it. On Apple platforms the system font switches to its display cut at large sizes on its own. Elsewhere Inter stands in without stylistic sets or leading adjustments. Mono appears only inside the code window.

### Hierarchy
- **Hero Display** (600; 28px, 34px from 420px, 40px from 641px, 56px from 1069px; line-height 1.07; −0.015em, easing to −0.005em at 56px): the name, once per page.
- **Display Large** (600; 32px, 40px from 768px; 1.1; −0.01em, then normal from 768px): section titles and the featured project's name.
- **Display Medium** (600; 28px, 34px from 768px; 1.2; −0.011em): the other project names and "Integration work."
- **Lead** (400; 21px/1.19, then 28px/1.14 with +0.007em from 768px): the one-line subcopy under a display title, balanced across lines and held to 22–34ch.
- **Tagline** (600, 21px, 1.19, +0.011em): the sub-nav name, h3 titles in grids and cards, and the contact email address.
- **Tagline Regular** (400, same metrics): the secondary project summaries.
- **Body** (400, 17px, 1.47, −0.022em): paragraphs, held to 46–60ch.
- **Body Strong** (600, 17px, 1.24): fact values and education titles.
- **Button** (400, 17px, line-height 1): pill labels. The compact sub-nav pill drops to 14px.
- **Caption** (400, 14px, 1.43, −0.016em): fact labels, tool lists, the board's helper line and skill-chip labels.
- **Caption Strong** (600, 14px, 1.29): credit values, experience dates (tabular figures) and footer column heads.
- **Fine** (400, 12px, line-height 1, −0.01em): global nav links and the copyright line.
- **Code** (mono 400; 11px, 12px from 640px, 13.5px from 768px; 1.75): code-window source. The console runs 12px, then 13px from 768px, at 1.8.
- **Keycap Legend** (500, max(0.19 × key unit, 9px), 1.1, no tracking): legends printed on caps. They sit in the Mac legend position at the top left and are centred only on arrows, the space bar, keyset keys, macro keys and the contact return key.
- Footer link lists are 14px with a relaxed 2.2 line-height.

### Named Rules
**The Apple-Tight Rule.** Display, body and caption sizes carry negative tracking (−0.005em to −0.022em). Only the 21px tagline and the 28px lead open up slightly (+0.011em, +0.007em).

**The 17px Rule.** Body copy is 17px at 1.47, never 16px.

**The Two-Weight Rule.** UI type is 400 or 600. Weight 500 exists only on keycap legends, where it is printing on a render, not UI type.

**The Full-Stop Title Rule.** Section and project-group titles are short sentences that end in a period ("Meet Jefferson.", "Under the hood.", "Let's talk."). Project names and h3 labels do not.

## Layout

The page is a vertical stack of full-bleed tiles with no gap between them. Each tile holds a centred column capped at 980px. Narrower caps apply inside it: the code window at 860px, skill chips at 780px and credit rows at 640px. The nav bars use the same 980px container.

- **Section padding:** 48px vertical and 20px horizontal on phones, 32px horizontal from 640px and 80px vertical from 768px. The hero uses 56px top and 64px bottom, rising to 64px and 96px from 768px.
- **Vertical rhythm:** title to lead is 8–12px, lead to body 16–24px, and body to the CTA row 28px, with 16px between pills. The render sits 48px below the CTAs (64px from 768px).
- **Tile sequence as built:** global nav (black), frosted sub-nav (parchment), hero (white), Meet (Tile 1), Under the hood (parchment), Work header (white), featured project (Tile 2), two projects side by side (white and parchment, stacked below 768px), case study (Tile 3), Integration work (parchment), How I work (white), Experience (parchment), Contact (Tile 1), footer (parchment).
- **Grids:** Meet puts the portrait beside the copy at 5fr/7fr from 768px. Capabilities run in 2 columns. Process steps run in 1, then 2 (640px), then 3 (1024px) columns. The case study's problem, build and result run in 3 columns from 768px. Experience cards use an 11rem date column, the skills sheet and the integration list a 14rem name column, and education runs in 2 columns from 768px. Credits auto-fit 8rem minimum columns, and the footer has 3 columns from 640px.
- **Responsive collapse:** below 640px the global nav drops its section links but keeps the logo mark and LinkedIn. Below 768px the sub-nav drops its status line but keeps the name and "Email me". The hero helper caption also hides below 768px, and the hero board shows only the name keys' and the return key's legends (the return key shows "↵").
- **Render sizing:** the hero board's key unit is min(62px, (100vw − 40px) / 15.6), so the board always fits the viewport. Keysets use clamp(52px, 13vw, 76px), and the featured keyset uses clamp(56px, 14vw, 104px). The split keyset uses clamp(36px, (100vw − 40px) / 7.6, 72px), so both halves and the gap between them always fit. The macro is min(72px, (100vw − 40px) / 9.6) and the contact return key 76px. Below 640px, code lines wrap with a hanging indent instead of scrolling.
- **Sticky and scroll:** the sub-nav sticks at the top (z 50). Anchor scrolling is smooth, with 72px of scroll padding.

### Named Rules
**The Tile Pulse Rule.** No two stacked tiles share a surface. The colour change is the only divider between sections. Inside a tile, rules are 1px: white at 15% on dark, black at 10% on light.

**The Pedestal Rule.** A render keeps at least 40px of air from the nearest block of copy. Only its own one-line caption may sit closer (24px).

## Elevation & Depth

The UI is flat. Tiles carry no shadow and no border. Utility cards are separated by a hairline, not a shadow. The only UI-level depth is the frosted sub-nav: Parchment at 80% with a 24px backdrop blur, 1.8 saturation and a 1px black-at-8% bottom edge. Real depth belongs to the rendered objects. They get the one product shadow where they rest on a tile, and inside a render depth is modelled the way the object is built.

### Shadow Vocabulary
- **Product shadow** (`box-shadow: rgba(0, 0, 0, 0.22) 3px 5px 30px 0`): every keyboard case (hero board, keysets, macro, contact return key), the code window and the share image's keycap strip.
- **Case machining** (`box-shadow: inset 0 1px 0 rgba(255, 255, 255, 0.95), inset 0 -3px 0 rgba(0, 0, 0, 0.07)`): the milled top and bottom edges of the aluminium case, layered with the product shadow.
- **Keycap skirt** (`box-shadow: 0 calc(var(--u) * 0.06) 0 <cap base>, 0 calc(var(--u) * 0.09) calc(var(--u) * 0.1) rgba(0, 0, 0, 0.12)`): the cap's base edge in its own darker tone plus a soft contact shadow. Pressed, it shortens to `0 calc(var(--u) * 0.012) 0 <cap base>, 0 calc(var(--u) * 0.03) calc(var(--u) * 0.05) rgba(0, 0, 0, 0.1)` while the cap travels 0.05 units down.
- **Chip skirt** (`box-shadow: 0 3px 0 <cap base>, 0 5px 8px rgba(0, 0, 0, 0.1)`): the same skirt at fixed skill-chip size.
- **Backlight** (`box-shadow: 0 0 calc(var(--u) * 0.18) calc(var(--u) * 0.04) <stripe colour>` at 85% opacity): light under a lit key. It sits below every cap, so it shows only in the plate gaps around that key.
- **Traffic-light ring** (`box-shadow: inset 0 0 0 0.5px rgba(0, 0, 0, 0.2)`): the hairline edge on the three window buttons. The window itself carries a 1px black-at-40% ring.

### Named Rules
**The One Shadow Rule.** One drop shadow, rgba(0, 0, 0, 0.22) 3px 5px 30px, falls only from a rendered object resting on a tile. It never goes on cards, pills, nav, tiles or text.

**The Material Depth Rule.** Inside a render, depth comes from the object's own construction: the zero-blur skirt edge in the cap's base tone, a soft contact shadow, inset machining, and gradients that shade the case and the sculpted top faces. None of it leaves the render.

## Shapes

Three UI grammars plus one object grammar. Full-bleed tiles are square (0px). Every acting button is a full pill (9999px). Containers are gently rounded at 18px: utility cards and the 4:5 portrait. The 8px compact utility rect from Apple's language appears only on the skip link. The 10px corner belongs to macOS: the code window and the skill chips' outer edge (8px on the chip's top face). The code window's Run control is a 6px toolbar rect, and the traffic lights are 12px circles.

Keycap geometry scales with the key unit (`--u`) instead of the UI radius scale:
- Case radius 0.42u, with 0.3u of padding.
- Cap radius 0.14u, with 0.045u of gap on each side of every key.
- A sculpted top face inset 5% top, 16% bottom and 0.073u on each side at a 0.1u radius, narrower than the skirt and lit by a radial gradient from 15% down. The side inset is a fixed share of the key unit, so wide keys (space, shift, return) keep a 1u key's thin side skirt.
- A legend box inset 11% top, 24% bottom and 0.137u on each side.
- Key widths in Mac units: 1, 1.25, 1.5, 1.75, 2, 2.25, 2.75 and 6.25.

The logo mark and favicon are a single keycap printed with a round-capped "J" (outer radius 22 and top face radius 15 on a 100 grid). The nav mark uses the graphite modifier colourway and the favicon the action colourway. The shared stroke icons (LinkedIn, Copy, Check) sit on a 24px grid with a 1.75 stroke, square caps and miter joins, rendered at 16–20px.

### Named Rules
**The Two Grammars Rule.** Actions are pills, containers are 18px, and tiles are square. Keycaps are the only other rounded shapes, and their radii come from the key unit, never from the UI scale.

### The Keyboard
The hero render: a 65% Mac-layout board on a 15 × 5 unit grid whose key codes match `KeyboardEvent.code`.
- **Build:** Silver Alpha letters and digits and Graphite Modifier mods and arrows. Esc is green. Enter is an Action Keycap labelled "Email me", and the 6.25u space bar reads "open to remote roles", centred.

## Do's and Don'ts

### Do:
- **Do** use the Action Blue pill (17px, 11px × 22px, at least 44px tall, 95% press) for every action, paired with a ghost pill when there are two. Keep "Email me" as the primary everywhere it appears.
- **Do** alternate Canvas, Parchment and Tile 1–3 edge to edge so that no two stacked tiles match, with 80px vertical padding (48px on phones).
- **Do** use Sky (#2997ff) for links and ghost pills on near-black tiles, Mist (#cccccc) for secondary copy there, and Secondary (#6e6e73) for secondary copy on light tiles.
- **Do** give every new project a keyset: five keys whose legends name real features, alternating the product's colourway (a top / side / base triple) with Silver Alpha.
- **Do** draw key state with travel and depth (0.05u drop, shortened skirt). The stripe glow is the afterglow: it comes on in 50ms and cools over 900ms.
- **Do** cycle the rainbow stripe in its fixed order (green, yellow, orange, red, purple, blue) with its paired legend colours.
- **Do** give every animated render a still, finished state under reduced motion: name keys lit, console complete, transitions off.
- **Do** end section titles with a period and keep each lead to a single balanced line of thought.

### Don't:
- **Don't** introduce a second UI accent. Stripe, keycap and syntax colours never become link, button, heading, border or background colours.
- **Don't** colour a keycap Action Blue unless it is a real link.
- **Don't** put the product shadow, or any drop shadow, on cards, pills, nav, tiles or text. It belongs only under keyboard cases and the code window.
- **Don't** use gradients as backgrounds or on UI elements. Gradients exist only as material shading on the keyboard case and the sculpted keycap faces.
- **Don't** set UI copy in weight 500. The only 500 is the printed keycap legend.
- **Don't** use #7a7a7a for text. It fails AA at caption size, so Secondary (#6e6e73) replaces it.
- **Don't** round or inset the tiles. They are square and full-bleed, and the colour change is the divider.
- **Don't** use Sky on light surfaces.
- **Don't** make keycap chips or keyset keys clickable or hoverable. They are static facts, one fact per key.
- **Don't** let the board block a key's default or bind a modifier shortcut. Its only command is typing a section's name, and the return key is its only link.
